# Video Game Sales Analysis and Prediction

This project explores video game sales records from 1980 to 2024 and compares four machine learning regression models for predicting recorded total sales. It covers data cleaning, exploratory data analysis (EDA), feature engineering, visualizations, model evaluation, and recommendations.

## Project objectives

1. Compare the number of records and recorded sales across game genres.
2. Compare recorded sales across North America, Japan, PAL, and Other regions.
3. Examine game release records by year and decade.
4. Explore the relationship between critic scores and total sales.
5. Compare recorded sales across platforms.
6. Train and evaluate four regression models for total sales.

## Dataset

The project uses the Kaggle dataset [Video Game Sales & Industry Data (1980-2024)](https://www.kaggle.com/datasets/bhushandivekar/video-game-sales-and-industry-data-1980-2024). The supplied raw CSV contains 64,016 game-platform records and 14 columns, including genre, platform, critic score, release date, and regional and total sales.

Sales values are expressed in millions of copies. Total sales are missing for 70.44% of the records, so sales summaries and model results use only the records with available values. Check the Kaggle page for the dataset's current license and terms before redistributing the data.

## Data preparation and features

- Trims whitespace from text fields and fills missing publisher and developer values with `Unknown`.
- Parses release and update dates and converts numeric fields to numeric types.
- Marks negative sales and critic scores outside the 1-10 range as missing.
- Sets release dates outside 1980-2024 to missing to align the date analysis with the dataset period.
- Removes exact duplicate rows and rows missing title, console, or genre. The supplied data has no exact duplicates and no missing values in those three required fields.
- Creates `release_year`, `release_decade`, `critic_score_category`, `regional_sales_sum`, and `na_sales_share` features.
- Keeps regional sales out of the model predictors because they are components of total sales and could cause target leakage.

Missing sales values are not replaced with zero. The regression models use records with known `total_sales`; missing numeric predictor values are imputed inside the model preprocessing pipeline.

## Exploratory analysis

The analysis and charts investigate genre counts and sales, regional sales, release trends, critic scores, platform sales, sales distribution, and correlations between regional sales. Sales totals are recorded totals in the dataset, not estimates of complete market totals, because regional coverage is incomplete.

## Machine learning models

The target is `total_sales`. The predictors are critic score, release year, console, and genre. The data is split into 80% training and 20% test records with `random_state=42`.

The models are K-Nearest Neighbors (KNN), Linear Regression, Decision Tree Regression, and Random Forest Regression. They are evaluated using Mean Absolute Error (MAE), Root Mean Squared Error (RMSE), and R-squared (R²). The model with the lowest test RMSE is selected as the best fit for this comparison.

### Results from the recorded run

| Model | MAE | RMSE | R² |
|---|---:|---:|---:|
| KNN | 0.310 | 0.760 | 0.210 |
| Random Forest | 0.304 | 0.769 | 0.191 |
| Linear Regression | 0.363 | 0.807 | 0.109 |
| Decision Tree | 0.340 | 0.965 | -0.273 |

KNN has the lowest RMSE in this train-test split. Random Forest has a slightly lower MAE. The modest R² values indicate that these models explain only a limited amount of variation in held-out sales. Results are an educational baseline; cross-validation and hyperparameter tuning have not been performed.

## Limitations and next steps

- Total sales are missing for most rows, which limits the amount and representativeness of training data.
- Critic scores are missing for 89.57% of records.
- The regional totals have different data coverage and should not be interpreted as complete market shares.
- The model comparison uses one random train-test split. Repeated cross-validation, a baseline model, and parameter tuning would provide a more reliable comparison.
- Additional predictors should only be included if they would be available at prediction time and do not leak information from the sales target.
